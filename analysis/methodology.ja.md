# 出題分析の方法

## 目的

学習者が「この論点を知っている」だけで終わらず、試験問題の条件を読んだ瞬間に判断できる状態を目指します。

## 1問から取り出す情報

### 知識点

条文名だけでなく、次の形に分解します。

```text
主体 + 行為 + 時点 + 要件 + 例外 + 効果
```

例えば、制限行為能力者の問題なら、年齢・同意の有無・行為の種類・日常生活行為の例外・取消しの可否を別々に確認します。

### 決定的事実

選択肢全体のうち、結論を変える事実を一つまたは少数に絞ります。これが分かると、長い事例でも読む順番が安定します。

### ひっかけ軸

同じ知識がどのように変形されるかをタグ化します。

- 主体軸：誰が行ったか、誰に効果が帰属するか
- 時点軸：契約前・契約時・契約後、期間の起算点・満了点
- 場所軸：事務所、案内所、自宅、勤務先など
- 要件軸：善意、無過失、同意、通知、記名など
- 数字軸：金額、割合、期間、人数
- 原則・例外軸：原則を覚えた後に例外を適用させる構造
- 手続軸：申請、説明、交付、記録、登録など
- 取引態様軸：自ら売主、代理、媒介、自ら賃貸など

### 反転条件

「どの一語・一事実を変えれば○と×が反転するか」を記録します。これは暗記の確認ではなく、要件の境界を確認するためのデータです。

## 2. 集計する指標

公開可能なデータでは、少なくとも次を集計します。

- 論点別の登場年度数
- 論点別の問題数・選択肢数
- ひっかけ軸別の登場数
- 原則・例外、主体、時点、数字などの要件タイプ
- 正誤問題、事例問題、組合せ問題などの出題形式
- 直近の誤答率、未演習率、復習回数

単純な出題回数だけで「重要」と決めず、頻度、失点リスク、要件の細かさ、他分野への波及を分けて評価します。

## 3. 正誤問題への変換基準

良い正誤問題には、次の条件を付けます。

1. 正誤が一意に定まる
2. 判断に必要な事実が問題文にある
3. 一つの主論点に集中している
4. 例外や否定語を意図的に置いた場合、その理由が説明できる
5. 解説が「結論・理由・決定的事実・反転条件」に分かれている
6. 出典、確認日、法令時点を確認できる

## 4. データ品質チェック

問題を追加したら、機械的な検証と人による確認を両方行います。

- 必須フィールドがあるか
- `answer` が `○` または `×` か
- `id` が重複していないか
- 問題文と解説の言語が一致しているか
- 正解と解説が矛盾していないか
- `source` が「自作」または確認可能な出典になっているか
- 法令の確認日があるか

機械検証は [`../scripts/validate_data.py`](../scripts/validate_data.py) で行います。
